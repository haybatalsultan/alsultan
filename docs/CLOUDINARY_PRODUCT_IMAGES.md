# Cloudinary Product Images

HaybatAlsultan uses Cloudinary as the permanent store for product media.

## Security model

- Uploads and deletions are server-side only.
- The Cloudinary API secret never appears in HTML or JavaScript.
- Only authenticated OWNER/SUPERVISOR accounts with `manage_product_images` may manage product images.
- OWNER management access remains protected by MFA.
- Files are validated with Pillow before upload.
- Accepted formats: JPEG, PNG, WEBP, AVIF.
- SVG and executable/raw uploads are not accepted.
- Maximum image size and maximum images per product are environment-configurable.
- Cloudinary folder/public IDs are generated by the server and cannot be supplied by the browser.
- Delete is POST + CSRF and is scoped to a ProductImage belonging to the requested Product.
- If Cloudinary deletion fails, the database image record is intentionally retained.

## Cloudinary organization

Dynamic folder mode:

`haybatalsultan/products/<PRODUCT_REFERENCE>/`

The product reference is immutable and generated server-side.

## Environment

Required:
- `CLOUDINARY_CLOUD_NAME`
- `CLOUDINARY_API_KEY`
- `CLOUDINARY_API_SECRET`

Optional limits:
- `PRODUCT_IMAGE_MAX_BYTES=5242880`
- `PRODUCT_IMAGE_MAX_COUNT=12`
- `PRODUCT_IMAGE_MAX_PIXELS=40000000`

Never commit `.env`.

## Delivery optimization

Storefront delivery URLs use Cloudinary transformations with automatic format and quality selection.
The original secure URL is kept in the database as a stable fallback.

## Production note

The current Cloudinary Free-plan role model may require an API key with broader permissions than desired.
Before production, prefer a dedicated key with the narrowest available permissions and rotate any development credentials.
